# ForZip — Forensic ZIP Tool  > Open-source, portable, auditable forensic compression utility with cryptographic verification and AES-256 encryption.  **Version:** 1.4.0   **License:** Apache License 2.0   **Author:** Claudio Andino — Patagonia Robot   **Contact:** claudio@patagoniarobot.com  ---  ## What is ForZip?  ForZip is a free, open-source forensic ZIP utility designed for digital forensic examiners, IT investigators, system administrators, and anyone who needs to package files with verifiable integrity. It produces standard ZIP archives with optional AES-256 encryption and generates a complete forensic report (`.txt`) documenting every operation, including hashes (MD5, SHA-1, SHA-256, SHA-512) of every file processed.  The tool is bilingual (English / Spanish — auto-detected from your operating system), entirely portable (no installation, no registry keys, no telemetry), and completely auditable — every line of source code is published under the Apache License 2.0.  ## Why ForZip?  Most ZIP utilities focus on compression speed or convenience. ForZip is built around a different priority: **reproducible, verifiable, court-defensible packaging of digital evidence**. Every operation is logged. Every hash is stored. Every report is accompanied by an external SHA-256 sidecar (`.sha256`) and a machine-readable manifest, so accidental corruption is detected. The manifest can additionally be **digitally signed** (CMS/PKCS#7) with the operator's X.509 certificate (`--sign-cert`), making tampering cryptographically evident. (Note: without a signature, the sidecar detects corruption, not malicious tampering — anyone who edits the report can recompute it.)  ## Key Features  - **Standard ZIP format** — compatible with 7-Zip, WinRAR, Windows Explorer, etc. - **AES-256 encryption** with optional password protection.
- **Digital signature** of the forensic manifest (CMS/PKCS#7) with the operator's X.509 certificate — verifiable independently (e.g. with OpenSSL).
- **Parallel hashing** of file batches for faster processing of many files. - **Cryptographically secure password generator** with configurable length (minimum 8) and character classes. Visually ambiguous characters (`0 O o I l 1 |`) are always excluded — a password that has to be transcribed or dictated by hand cannot contain characters the operator may misread. - **Quick hash window** — *Calculate hash* from the Explorer context menu opens a single lightweight window (7-Zip style) with name, path, size, timestamp and hashes, ready to copy to the clipboard or export as a `.txt` forensic report, without launching the full application. - **Checksum-verified updates** — ForZip can check for a newer release and install it at your request, verifying the published SHA-256 of the download before replacing anything. It never updates itself in the background: the report declares which version produced each package, and many labs run validated, frozen tool versions. - **Multi-hash support** — MD5, SHA-1, SHA-256, SHA-512 (any combination, all, or none). - **Forensic report** in `.txt` format — UTF-8 with BOM, includes operator data, full file listing, individual hashes, and a an external SHA-256 sidecar (`.sha256`) plus a machine-readable `.manifest.json` for automated verification. - **Evidence verification** — re-hash the contents of a previously generated archive against its forensic manifest (`.manifest.json`) and get a per-file verdict (OK / altered / missing / extra), plus verification of the archive's global SHA-256. - **Hash batch mode** — hash files without zipping them. - **Six compression levels** — from Store (no compression) to Maximum.
- **Split archives (multi-volume)** — optionally divide the output into fixed-size volumes (`.001`, `.002`, …), 7-Zip style. Each volume is hashed (SHA-256) individually in the forensic manifest, in addition to the global hash of the logical archive; extraction and verification auto-detect and reassemble the volumes transparently. - **Bilingual UI** — Spanish and English, auto-detected from the system locale. - **Modern interface** — dark theme by default, drag-and-drop, real progress by bytes. - **CLI mode** — full command-line interface for automation and scripting. - **Fully portable** — single executable, no installer, no registry, no admin rights. - **Windows x64** — the GUI targets `net8.0-windows` (it uses the registry for the optional Explorer context-menu integration), so it runs on Windows 10/11 only. `ForZip.Core` and the CLI project are plain `net8.0` and carry no Windows-specific dependency, so a cross-platform CLI build is feasible, but no Linux or macOS binaries are published today.  ## Disclaimer  ForZip is provided "AS IS", without warranty of any kind, express or implied, including but not limited to the warranties of merchantability, fitness for a particular purpose, and non-infringement.  **ForZip is provided for forensic, educational, and general-purpose use. Download `ForZip.exe` (GUI) or `ForZip.Cli.exe` (command line) from the [Releases page](https://github.com/PatagoniaRobot/ForZip/releases/latest). 2. **Verify what you downloaded** against the `.sha256` published next to it — see below. 3. Save it anywhere — your desktop, a USB drive, or a forensic toolkit folder. 4. Double-click to run.  That is it. No installer, no admin rights required, no registry keys created.  ### Verifying the download  Every release publishes a `.sha256` alongside each executable. Verifying takes one command and is worth the ten seconds — you are about to run this on evidence.  ``` certutil -hashfile ForZip.exe SHA256 ```  Compare the result with the contents of `ForZip.exe.sha256`, or on a machine with GNU coreutils: `sha256sum -c ForZip.exe.sha256`.  Once you are on version 1.3.0 or later, ForZip can check for updates by itself from **About → Check for updates**, and from 1.4.0 it can install them — always at your request, and only after verifying the published checksum of what it downloaded.  ### A note on the SmartScreen warning  ForZip's executables are **not yet signed with an Authenticode certificate**, so Windows will show a *"Windows protected your PC"* screen with *"Unknown publisher"* the first time you run it. You need to click *More info → Run anyway*. This is expected for now; verifying the SHA-256 above is what actually tells you the file is the one that was published. Code signing is planned.  ## Quick Start  ### GUI Mode  1. Launch `ForZip.exe`. 2. Drag the file or folder you want to package onto the main window. 3. Choose your options (compression level, encryption, hashes, report). 4. Click **Process**. 5. The ZIP and the forensic report are saved next to your input.  ### CLI Mode  ``` ForZip.exe zip -i "C:\Evidence\Case42" -o "C:\Output\Case42.zip" --hash sha256,sha512 --report "C:\Output\Case42.report.txt" --level 5 ```  Run `ForZip.exe --help` for the full list of CLI flags.  ## Building from Source  ForZip is built with .NET 8 and Avalonia UI 11.  ```bash git clone https://github.com/PatagoniaRobot/ForZip.git cd ForZip dotnet build -c Release dotnet test dotnet publish src/ForZip.GUI/ForZip.GUI.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o Publish/GUI dotnet publish src/ForZip.Cli/ForZip.Cli.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o Publish/CLI ```  The output is a single `ForZip.exe` in `Publish/GUI/` and a single `ForZip.Cli.exe` in `Publish/CLI/`. `publish.bat` in the repository root runs both commands.  Note that these folders also accumulate the runtime's own `config.json` and `Logs/` once you run the executable from them — never redistribute the folder wholesale, only the executables themselves.  ## Documentation  Contributor and pull-request documentation lives in the `Documentation/` directory:  - [`CONTRIBUTING.md`](Documentation/CONTRIBUTING.md) — Bilingual (English / Spanish) contributor guide: project layout, forensic integrity model, development setup, coding standards, and the pull-request checklist.  ## Contributing  Contributions are welcome.
