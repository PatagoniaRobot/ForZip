# ForZip — Forensic ZIP Tool  > Open-source, portable, auditable forensic compression utility with cryptographic verification and AES-256 encryption.  **Version:** 2.0.0   **License:** Apache License 2.0   **Author:** Claudio Andino — Patagonia Robot   **Contact:** claudio@patagoniarobot.com  ---  ## What is ForZip?  ForZip is a free, open-source forensic ZIP utility designed for digital forensic examiners, IT investigators, system administrators, and anyone who needs to package files with verifiable integrity. It produces standard ZIP archives with optional AES-256 encryption and generates a complete forensic report (`.txt`) documenting every operation, including hashes (MD5, SHA-1, SHA-256, SHA-512) of every file processed.  The tool is bilingual (English / Spanish — auto-detected from your operating system), entirely portable (no installation, no registry keys, no telemetry), and completely auditable — every line of source code is published under the Apache License 2.0.  ## Why ForZip?  Most ZIP utilities focus on compression speed or convenience. ForZip is built around a different priority: **reproducible, verifiable, court-defensible packaging of digital evidence**. Every operation is logged. Every hash is stored. Every package is accompanied by a machine-readable manifest with the hash of every file and of the package itself; the human-readable report is generated from it on request. The manifest can additionally be **digitally signed** (CMS/PKCS#7) with the operator's X.509 certificate (`--sign-cert`), making tampering cryptographically evident. (Note: without a signature, whoever changes the package can change the manifest too. What proves nothing changed is the package SHA-256 written down in the chain of custody record, or the signature.)  ## Key Features  - **Standard ZIP format** — compatible with 7-Zip, WinRAR, Windows Explorer, etc. - **AES-256 encryption** with optional password protection.
- **Digital signature** of the forensic manifest (CMS/PKCS#7) with the operator's X.509 certificate — verifiable independently (e.g. with OpenSSL).
- **Parallel hashing** of file batches for faster processing of many files. - **Cryptographically secure password generator** with configurable length (minimum 8) and character classes. Visually ambiguous characters (`0 O o I l 1 |`) are always excluded — a password that has to be transcribed or dictated by hand cannot contain characters the operator may misread. - **Quick hash window** — *Calculate hash* from the Explorer context menu opens a single lightweight window (7-Zip style) with name, path, size, timestamp and hashes, ready to copy to the clipboard or export as a `.txt` forensic report, without launching the full application. - **Checksum-verified updates** — ForZip can check for a newer release and install it at your request, verifying the published SHA-256 of the download before replacing anything. It never updates itself in the background: the report declares which version produced each package, and many labs run validated, frozen tool versions. - **Multi-hash support** — MD5, SHA-1, SHA-256, SHA-512 (any combination, all, or none). - **Forensic manifest and report** — every package gets a machine-readable `.manifest.json` (operator, case, computer, every file with its hashes, the package hash) for automated verification; the forensic report is generated from it on request, after packaging or after verifying (with the verdict), as a printable HTML page that opens with a double click or as `.txt`. - **Evidence verification** — re-hash the contents of a previously generated archive against its forensic manifest (`.manifest.json`) and get a per-file verdict (OK / altered / missing / extra), plus verification of the archive's global SHA-256. - **Hash batch mode** — hash files without zipping them. - **Six compression levels** — from Store (no compression) to Maximum.
- **ZIP or 7z** — package as a classic ZIP or as a 7z written by ForZip's own engine (LZMA2, every core, no solid mode so damage never spreads; with a password it also encrypts the file names). Extraction and verification recognise either format by its signature, including 7z archives made by 7-Zip. The Reserved profile always uses ZIP. - **Opens evidence in other formats** — RAR (every version, encrypted and multi-volume included), TAR, TAR.GZ/BZ2/XZ, GZ, BZ2, XZ and ISO 9660 (Joliet), recognised by signature; links and devices are documented, not created; dangerous names are sanitised and listed. - **Split archives (multi-volume)** — optionally divide the output into fixed-size volumes (`.001`, `.002`, …), 7-Zip style. Each volume is hashed (SHA-256) individually in the forensic manifest, in addition to the global hash of the logical archive; extraction and verification auto-detect and reassemble the volumes transparently. - **Bilingual UI** — Spanish and English, auto-detected from the system locale. - **Modern interface** — dark theme by default, drag-and-drop, real progress by bytes. - **CLI mode** — full command-line interface for automation and scripting. - **Fully portable** — single executable, no installer, no registry, no admin rights. - **Windows x64** — the GUI targets `net10.0-windows` (it uses the registry for the optional Explorer context-menu integration), so it runs on Windows 10/11 only. `ForZip.Core` and the CLI project are plain `net10.0` and carry no Windows-specific dependency, so a cross-platform CLI build is feasible, but no Linux or macOS binaries are published today.  ## Disclaimer  ForZip is provided "AS IS", without warranty of any kind, express or implied, including but not limited to the warranties of merchantability, fitness for a particular purpose, and non-infringement.  **ForZip is provided for forensic, educational, and general-purpose use. Download `ForZip.exe` (GUI) or `ForZip.Cli.exe` (command line) from the [Releases page](https://github.com/PatagoniaRobot/ForZip/releases/latest). 2. **Verify what you downloaded** against the `.sha256` published next to it — see below. 3. Save it anywhere — your desktop, a USB drive, or a forensic toolkit folder. 4. Double-click to run.  That is it. No installer, no admin rights required, no registry keys created.  ### Verifying the download  Every release publishes a `.sha256` alongside each executable. Verifying takes one command and is worth the ten seconds — you are about to run this on evidence.  ``` certutil -hashfile ForZip.exe SHA256 ```  Compare the result with the contents of `ForZip.exe.sha256`, or on a machine with GNU coreutils: `sha256sum -c ForZip.exe.sha256`.  Once you are on version 1.3.0 or later, ForZip can check for updates by itself from **About → Check for updates**, and from 1.4.0 it can install them — always at your request, and only after verifying the published checksum of what it downloaded.  ### A note on the SmartScreen warning  ForZip's executables are **not yet signed with an Authenticode certificate**, so Windows will show a *"Windows protected your PC"* screen with *"Unknown publisher"* the first time you run it. You need to click *More info → Run anyway*. This is expected for now; verifying the SHA-256 above is what actually tells you the file is the one that was published. Code signing is planned.  ## Quick Start  ### GUI Mode  1. Launch `ForZip.exe`. 2. Drag the file or folder you want to package onto the main window. 3. Choose your options (compression level, encryption, hashes, report). 4. Click **Process**. 5. The ZIP and its manifest are saved next to your input; write the package fingerprint down in your chain of custody record, and use *Save report…* if you want the text report.  ### CLI Mode  ``` ForZip.exe zip -i "C:\Evidence\Case42" -o "C:\Output\Case42.zip" --hash sha256,sha512 --level 5  ForZip.exe verify -m "C:\Output\Case42.zip.manifest.json" --write-report "C:\Output\Case42.report.txt" ```  Run `ForZip.exe --help` for the full list of CLI flags.  ## Building from Source  ForZip is built with .NET 10 and Avalonia UI 11.  ```bash git clone https://github.com/PatagoniaRobot/ForZip.git cd ForZip dotnet build -c Release dotnet test dotnet publish src/ForZip.GUI/ForZip.GUI.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o Publish/GUI dotnet publish src/ForZip.Cli/ForZip.Cli.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o Publish/CLI ```  The output is a single `ForZip.exe` in `Publish/GUI/` and a single `ForZip.Cli.exe` in `Publish/CLI/`. `publish.bat` in the repository root runs both commands.  Note that these folders also accumulate the runtime's own `config.json` and `Logs/` once you run the executable from them — never redistribute the folder wholesale, only the executables themselves.

## Reserved Profile and the Sealed `.fzs` Envelope

An encrypted ZIP protects the content but not the wrapper: the file name and the manifest are still in plain sight. Once the package is uploaded to third-party cloud storage, that is enough for an indexer to learn the case number, the number of files and the names of the evidence — and enough for a sync client to unpack whatever it finds on its own.

Since 2.0.0, the **Reserved profile** encloses the finished package — ZIP, manifest and signature — in a **sealed `.fzs` envelope**: AES-256-GCM in 1 MiB authenticated chunks, with the key derived from the password using PBKDF2-HMAC-SHA256 at 600,000 iterations. The envelope reveals no file names, no file count, no case number, no operator — only its size and the date it was sealed.

Sealing produces three pieces with three different destinations:

- **`FZS-xxxxxxxx.fzs`** — the envelope. This is the only thing that goes to the cloud.
- **`FZS-xxxxxxxx.receipt.json`** — the public receipt, for the case file. It declares the hash of the *envelope*, not of the content, so anyone can verify the envelope was not altered **without the password** and without being given access to anything.
- **The key handover record** — for the in-person act in which the password is handed over against a signed receipt. It is never uploaded.

Verification has two levels and ForZip picks the right one by itself: with no password it issues the public verdict (envelope intact or altered, plus signer and date); with the password it adds the usual per-file verdict.

```
ForZip.Cli.exe zip -i "C:\Evidence\Case42" -o "C:\Output\Case42.zip" --profile reserved --acta acta.txt
ForZip.Cli.exe seal   -i ./package -o ./out --gen-password --acta acta.txt
ForZip.Cli.exe unseal -i FZS-c8faa4d8.fzs -o ./opened
ForZip.Cli.exe verify -i FZS-c8faa4d8.fzs
```

### The format is open

The security of the envelope rests on the password, never on the secrecy of the format. A cryptographic format whose protection depends on nobody knowing how it works is not a secure format. So `.fzs` is published, not hidden:

- [`Documentation/Formato_FZS_v1.md`](Documentation/Formato_FZS_v1.md) — the full specification: binary layout, KDF parameters, nonce and AAD construction, and the verification algorithm, at the level of detail needed to write your own extractor without reading the C# code. (Written in Spanish.)
- [`Tools/fzs_extract.py`](Tools/fzs_extract.py) — a standalone extractor, about a hundred lines of Python 3, needing only the standard library plus `cryptography`. It decrypts an envelope and dumps its contents; nothing else. It was written from the specification rather than from the code, and an integration test verifies on every format change that the two agree byte for byte. A copy also travels inside every envelope.
- [`Tools/Open_FZS.html`](Tools/Open_FZS.html) — an opener for whoever *receives* an envelope: a single, self-contained HTML page that runs offline in Microsoft Edge or Google Chrome. Double-click it, choose the `.fzs`, type the password, choose where to save; out comes the inner ZIP. No installation, no administrator rights, no PowerShell, no executable without reputation. A Content-Security-Policy in the page itself forbids every network connection, and the code is unminified so anyone can read it. It decrypts block by block and writes through the browser's transactional file writer, so memory stays flat on envelopes of tens of gigabytes and nothing half-decrypted is ever left behind. It neither unpacks nor runs the evidence. ForZip leaves a copy next to every envelope it seals, and the key handover record states the page's SHA-256 so the recipient can check it is the original. Its decryption core is tested against ForZip and the Python extractor byte for byte, in Node, taken straight from the published page.

That is what neutralizes the risk a format of one's own introduces: ten years from now, somebody with Python opens the evidence even if ForZip no longer runs on the operating system of the day.

### Custody of the binary that sealed it

The report declares which version of ForZip produced each package. The other half is the organization's procedure, not the program's: **archive the exact executable of every version used in production, together with its SHA-256, in the organization's internal registry** — not in the cloud. This is the laboratory practice of working with validated, frozen tool versions, and it is what allows a verification to be reproduced years later with the same tool that produced it. Without it, the published specification and the standalone extractor only get you halfway.

### What this version does not solve

The operator is entitled to know the limits of the tool:

- **The size of the envelope reveals the order of magnitude of the content.** There is no padding.
- **A copy of the evidence still exists on a third party's infrastructure.** Sealing removes the visible information, not the institutional exposure nor the applicable jurisdiction. The decision to upload sensitive material to third-party cloud storage should rest on a written protocol of the organization, not on an individual operator's judgment.
- **The password is the only factor.** If it is lost, the content is unrecoverable; if it leaks, the protection is gone entirely. In-person handover against a signed receipt is part of the security system, not administrative paperwork.
- **The executables are still unsigned (no Authenticode).** Pending since 1.3.0.
